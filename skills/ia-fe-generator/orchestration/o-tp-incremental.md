# o-tp-incremental

## 职责

负责 TP 类型优化需求 FE 的增量构建编排(基于历史FE进行增量变更)。

## 初始化阶段

### Action 0: 续接恢复检查

若存在进行中的FE文档,检查workflow_id并恢复执行。

### Action 1: 验证环境与历史FE加载

1. 读取历史FE文档(必需输入 `FE_HISTORICAL`)
2. 验证历史FE状态为"completed"
3. 读取用户输入的优化需求内容(对话或文档)
4. 创建新版本FE文档,继承历史FE的基础信息

### Action 2: 知识库初始化

加载业务知识库,对比历史FE中已使用的业务术语。

### Action 3: 检测增量输入

检查用户是否提供优化需求的详细文档(可选)。

### Action 4: 确认增量执行序列

识别哪些要素需要增量变更(基于用户输入和差异分析)。

## 要素执行循环

对需要变更的要素执行 `element-runner(mode="incremental")`。

## 完成阶段

### Action A: 知识沉淀建议

识别新增的业务术语和规则。

### Action B: 质量检查

验证增量变更的完整性和语法正确性。

### Action C: 最终状态更新

标记新版本FE为"completed"。

## 当前状态

骨架版本,待后续完整实现。
