# m-fe-requirement-type — 需求类型定性

> 通过后台关键词匹配判定需求类型(TP/AP/AI/IT),生成后台标注记录判定依据和设计约束提示。无需用户交互,基于已收集信息自动分析。

## 目标

**目标说明**

后台自动分析已收集信息中的关键词(需求名称/业务背景/业务目标/痛点),判定需求类型,生成后台标注和设计约束提示。

**输出物**

- 后台标注记录(requirement_type、判定依据、设计约束提示)
- 写入 ongoing.md requirement_type 字段

**成功标准**

- 需求类型已判定(TP/AP/AI/IT之一)
- 判定依据清晰(关键词匹配说明)
- 设计约束提示已生成(针对该类型的架构设计注意事项)
- 无需用户交互,后台自动完成

---

**依赖要素**

| 依赖要素 element_id | 原因 |
|----------------------|------|

## 执行步骤

**Step 1: 后台关键词分析** `[自动]`

读取已收集信息:
- 需求名称(original-requirement)
- 业务背景-目标和价值(business-background)
- 原始需求关键信息提取矩阵(original-requirement)

提取关键词并匹配。

**Step 2: TP类关键词匹配** `[自动]`

**关键词列表**:
- 订单、支付、交易、购买、结算、审批、库存、采购、销售、发货、退货、报销、申请、核销、冻结、解冻、转账、充值

**匹配逻辑**:
- 若关键词出现频率 >= 1:
  - 判定为 TP 类型
  - 写入 ongoing.md requirement_type = "TP"
  - 生成后台标注:

```yaml
requirement_type: "TP"
判定依据:
  关键词匹配: "需求名称/业务目标中包含关键词'订单'、'支付'、'审批'"
  匹配位置: "{需求名称}中出现'审批',业务目标中出现'订单处理'"
设计约束提示:
  - 关注 ER 设计(实体关系建模)
  - 关注事务一致性(ACID 特性)
  - 关注并发控制(高并发场景下的锁机制)
  - 关注业务流程完整性(端到端流程闭环)
```

**Step 3: AP类关键词匹配** `[自动]`

**关键词列表**:
- 报表、统计、分析、看板、指标、数据可视化、趋势、对比、汇总、BI、数据仓库、ETL、维度、报表生成

**匹配逻辑**:
- 若关键词出现频率 >= 1:
  - 判定为 AP 类型
  - 写入 ongoing.md requirement_type = "AP"
  - 生成后台标注:

```yaml
requirement_type: "AP"
判定依据:
  关键词匹配: "需求名称/业务目标中包含关键词'报表'、'分析'、'看板'"
  匹配位置: "{需求名称}中出现'报表',业务目标中出现'数据分析'"
设计约束提示:
  - 关注维度建模(OLAP 设计)
  - 关注 ETL 设计(数据抽取、转换、加载)
  - 关注数据仓库(数据分层:ODS/DWD/DWS/ADS)
  - 关注数据查询性能(OLAP 查询优化)
```

**Step 4: AI类关键词匹配** `[自动]`

**关键词列表**:
- 预测、推荐、识别、智能、算法、机器学习、深度学习、自然语言处理、图像识别、语音识别、智能客服、个性化推荐、风控模型、模型训练

**匹配逻辑**:
- 若关键词出现频率 >= 1:
  - 判定为 AI 类型
  - 写入 ongoing.md requirement_type = "AI"
  - 生成后台标注:

```yaml
requirement_type: "AI"
判定依据:
  关键词匹配: "需求名称/业务目标中包含关键词'预测'、'推荐'、'识别'"
  匹配位置: "{需求名称}中出现'智能',业务目标中出现'个性化推荐'"
设计约束提示:
  - 关注数据管道(数据采集、清洗、标注)
  - 关注模型评估(AUC/F1/准确率等指标)
  - 关注特征工程(特征提取、特征选择)
  - 关注模型部署(在线推理/离线推理)
```

**Step 5: IT类关键词匹配** `[自动]`

**关键词列表**:
- 集成、接口、同步、对接、API、数据迁移、系统对接、第三方系统、数据交换、消息队列、同步机制

**匹配逻辑**:
- 若关键词出现频率 >= 1:
  - 判定为 IT 类型
  - 写入 ongoing.md requirement_type = "IT"
  - 生成后台标注:

```yaml
requirement_type: "IT"
判定依据:
  关键词匹配: "需求名称/业务目标中包含关键词'集成'、'接口'、'同步'"
  匹配位置: "{需求名称}中出现'系统集成',业务目标中出现'数据同步'"
设计约束提示:
  - 关注接口设计(Restful/GraphQL/SOAP)
  - 关注数据同步(实时/批量/增量同步)
  - 关注容错机制(超时/重试/熔断/降级)
  - 关注协议适配(HTTP/MQ/TCP)
```

**Step 6: 多类型匹配处理** `[自动]`

若匹配到多个类型关键词(如同时包含"订单"和"报表"):
- 优先级: TP > AP > AI > IT
- 判定为优先级最高的类型
- 在后台标注中注明多类型匹配情况:

```yaml
requirement_type: "TP"  # 优先级最高
判定依据:
  关键词匹配: "包含'订单'(TP类)和'报表'(AP类)关键词"
  多类型匹配: "TP类优先级高于AP类,判定为TP"
  匹配位置: "{需求名称}中出现'订单处理',业务目标中出现'报表生成'"
设计约束提示:
  - 关注 TP 类设计约束(ER设计、事务一致性、并发控制)
  - 同时包含 AP 特征,后续补充报表设计注意事项
```

**Step 7: 写入文档** `[自动]`

- 写入 ongoing.md requirement_type 字段
- 生成后台标注记录(存入 FE 文档后台备注区)
