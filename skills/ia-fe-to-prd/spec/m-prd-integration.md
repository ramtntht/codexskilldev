# m-prd-integration — 集成设计

> 基于应用架构系统边界表格，为每个外部依赖设计集成方式（API/MQS/数据集成），输出集成点清单、接口详细设计、消息队列设计和数据集成设计。

---

## 目标

**目标说明**

集成设计将应用架构"有哪些外部依赖"细化为"如何技术实现对接"，是连接产品需求和技术实现的关键桥梁。核心是为每个集成点选择合适的集成方式，并给出足够详细的接口/消息/数据规格。

**输出物**

- 集成点清单表格（集成点编号 | 集成点名称 | 对接系统 | 集成方式 | 方式选择依据 | 调用触发场景）
- API 类型集成详细设计（接口配置 + 输入参数表 + 输出参数表 + 处理逻辑 Mermaid + 异常处理策略）
- MQS 类型集成设计（消息主题 + 消息格式 + 生产者/消费者 + 失败重试策略）
- 数据集成设计（数据源 + 同步方式 + 同步频率 + 字段映射规则）

**成功标准**

- 集成点清单覆盖应用架构系统边界表格中的所有外部依赖
- 每个集成点有明确的集成方式和选择依据（不填"待定"）
- API 类型集成有输入/输出参数表格

**依赖要素**

| 依赖要素 element_id | 原因 |
|----------------------|------|
| `app-architecture` | 系统边界表格定义了所有外部依赖（集成点来源） |

**必要输入**

- PRD要素: `PRD应用架构-系统边界表格`（含依赖系统、依赖类型、接口方式）
- FE要素: `FE需求类型-TP类(外部依赖说明-依赖详情)`（可选，如FE已设计依赖详情）

> **跳过条件**：若应用架构系统边界表格中无任何外部依赖，本要素自动标记为 SKIP 并告知用户。本要素为 optional。

### 设计约束

| 约束编号 | 级别 | 规则 | 验证方法 |
|----------|------|------|---------|
| `DC-INT-001` | `MUST` | 集成点清单必须覆盖系统边界表格的所有外部依赖，不得遗漏 | 对照系统边界表格逐行检查 |
| `DC-INT-002` | `MUST` | 集成方式字段必须明确为以下之一：REST API / MQS / DB直连 / 文件交换，禁止填"待定" | 检查每行集成方式字段是否有明确选择 |
| `DC-INT-003` | `SHOULD` | API 类型集成应包含异常处理策略（超时重试次数、降级方案） | 检查 API 集成是否有异常处理说明 |

## 执行步骤

**Step 1：从系统边界引用集成点，确定集成方式** `[交互]`

读取应用架构章节系统边界表格，为每个外部依赖系统推荐集成方式（基于：实时性要求 → API；高并发解耦 → MQS；历史数据同步 → 数据集成；文件批量 → 文件交换），推荐同时说明依据。

> **交互提示**：展示集成方式推荐表，询问用户："以上集成方式推荐是否合理？是否有需要调整的集成方式？"

---

**Step 2：API 集成详细设计** `[交互]`

为每个 API 类型集成点设计接口规格，包括：
- 接口 URL、协议（REST/SOAP）、认证方式（API Key/OAuth）
- 输入参数表格（参数名 | 类型 | 来源字段 | 映射规则）
- 输出参数表格（参数名 | 类型 | 目标字段）
- 处理逻辑 Mermaid 流程图
- 异常处理策略

> **交互提示**："请确认 API 接口的参数映射规则是否符合对接系统的实际接口规格？"

---

**Step 3：MQS / 数据集成设计** `[自动]`

基于 FE 外部依赖详情，为 MQS 类型设计消息主题、格式、重试策略；为数据集成类型设计同步方式、频率、字段映射。
